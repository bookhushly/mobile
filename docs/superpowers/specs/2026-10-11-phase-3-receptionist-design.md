# Phase 3 — Receptionist (front desk) mode (design)

**Status:** decided 2026-10-11 under the owner's standing instruction to make every call ("Make all decisions by weighing them properly for this project, proceed to the next phase"); each call is recorded in §2 with why and what it costs if wrong. · **Branch:** `feat/phase-3-receptionist` · **Builds on:** UI-A kit, UI-B entry flow · **Requirements:** FR-4.1–FR-4.10 (FR-4.11 out), DECISION-2 (online-only), D10 (tablet two-pane in v1), acceptance 16–22 · **Backend:** verified against web `origin/main` @ `30c7da90` + the production schema snapshot (`receptionist-contract` findings, folded into `docs/BACKEND_STATUS.md` §4 by this phase) · **References:** `docs/design-references/2026-10-11-phase-3-receptionist-mobbin.md`.

## 1. Goal and success

A receptionist signs in on a phone or tablet and runs the front desk without the web dashboard: sees today at a glance, checks a guest in by typing or scanning their code (preview → confirm), checks guests out, moves a booking to another room when the assigned one is blocked, and keeps the room board current. Every server refusal is shown in words; a lost connection is never shown as a refusal.

Done when: acceptance 16–22 pass on the Moto G06 against production with a receptionist created through the vendor staff panel (the real flow) and a real paid test booking; `tsc`, lint and jest pass; the phone checklist's Phase 3 part passes.

## 4. Check-in outcomes (words shown)

| Result                                       | Shown                                                                                                            |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Code not the right shape                     | inline field error (R14)                                                                                         |
| No booking with that code (RLS read empty)   | "No booking with code ABC12345 at <hotel>. Check the code with the guest."                                       |
| `cancelled` (preview or 400)                 | "This booking was cancelled." No button.                                                                         |
| payment ≠ completed / `not_paid`             | "Payment hasn't been completed for this booking. The guest can pay on the Bookhushly app or website." No button. |
| already checked in / checked out             | "Already checked in at 10:42" / "This guest checked out on 12 Oct."                                              |
| `room_occupied`                              | "Room 204 still has a guest checked in." + **Choose another room**                                               |
| `room_unavailable`                           | "Room 204 is under maintenance." + **Choose another room**                                                       |
| `forbidden`                                  | "You can't check in guests at this hotel."                                                                       |
| 429 / timeout / network / 5xx / `unexpected` | neutral "Couldn't confirm" + **Check again** (R3) / R17                                                          |
| 401 after refresh fails                      | existing session-expired flow                                                                                    |

All refusals use the danger/warning tone with icon + text; transient states use the neutral tone. Haptic on success and refusal (kit feedback).

## 6. Error handling and freshness

- Reads: a failed first load shows `ErrorState` with **Try again** (transient wording); a failed background refetch keeps the old data and shows the "Updated …" line.
- Actions: one at a time per booking; buttons show progress and are disabled while sending; no automatic re-post (R3).
- Sign-out: no outbox here (online-only), so sign-out is immediate; the query cache and shift log are cleared.

## 7. Accessibility and motion

Targets ≥ 44 pt; status always word + icon/dot; count cells read as "Arriving, 4"; success and refusal announced (kit `announce`); search and code fields labelled; sheets scroll at the largest text; Reduce Motion: no sheet slide, no tick animation (kit already handles this). Tablet two-pane keeps focus order list → detail.
